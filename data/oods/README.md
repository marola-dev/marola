# OODS — an open ocean data store

A git-versioned store of Brazilian bathing-water samples: the raw files exactly as the monitoring
institute served them, plus Parquet partitions rebuilt deterministically from them. One adapter per
institute, one common schema, DuckDB SQL views that union every state
([MIP-0056](../../docs/mips/MIP-0056-oods-open-ocean-data-store.md)).

Nothing here is generated by an LLM and nothing is re-derived: a verdict is the agency's own.

## Sources

`sources.json` is the registry. The first and so far only source is **IMA/SC** (`ima-sc`) — the
Instituto do Meio Ambiente de Santa Catarina's bathing-water programme, whose portal publishes a
per-beach CSV history back to 2003. Its weekly bulletin PDF is a second channel: what is stored is
the rows parsed out of each bulletin (`raw/ima-sc/bulletins/YYYY-MM-DD.jsonl`), never the PDF, and
the manifest keeps the PDF's URL and sha256. A day the CSV export already carries is not stored
twice — the export has the indicator count and the collection time, the bulletin neither.

## Licence

**None granted.** IMA publishes no licence, terms of use, or open-data statement for this data, and
it is not on `dados.sc.gov.br`. It is public administrative information under the Lei de Acesso à
Informação (Lei 12.527/2011), which is the basis Brazilian civic-data projects cite — but that is
not a licence grant, so no licence is claimed here for the source data, and no CC badge is shown
(MIP-0056 §4.5). The decision on how to publish it is open (MIP-0056 §11); until it lands, treat
these files as a redistributed copy of IMA's public data, attributed to IMA/SC.

The code that produces the store is marola's own and is licensed with the repository.
