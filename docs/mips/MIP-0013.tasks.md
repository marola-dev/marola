## Sequencing notes

- Strictly sequential in practice, not parallel: task 1 is the only real fan-out point (2/3/4 all
  depend only on 1 and could run in parallel with each other), but 5/6 are the actual experiment
  and must run after 1-4 exist, in order (6 needs 5's own PR as one half of the comparison).
- Tasks 5 and 6 are genuinely different in kind from 1-4: they require *using* OpenCode
  interactively on a real task, not just writing config — a human (or an agent with real terminal
  access to run `opencode`/`just jo` live, not just edit files) does these, not a config-only
  automation pass. Flagged here so a future run doesn't try to fake task 5/6 by writing the
  comparison table without actually running OpenCode.
- Task 4's attribution wording is gated on OQ1 (§11) being resolved first — don't write the
  `AGENTS.md` prose change speculatively; if OQ1 turns out to need the `opencode-git-trailers`
  plugin, task 4 gains that as a real dependency, not assumed here.
