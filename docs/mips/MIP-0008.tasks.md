Decisions taken for v1 (MIP §11), so that the tasks above are unambiguous:

1. **Native-image: yes.** The spike (2026-09-05, GraalVM CE 25.2.4 = JDK 25.0.4, sbt-native-image
   0.5.0, Kyo 1.0.0-RC5, Scala 3.9.0): the image builds in 44 s once slf4j/logback/Jackson are
   initialised at build time (the first two failures were exactly those, reached through
   `azure-monitor`'s static logger and the MCP SDK's Jackson); the 69 MB binary runs the live
   `--brief` path in 35 s wall / 75 MB RSS (all of it Overpass/Open-Meteo). `--summarize` needs the
   compiled prompts as resources — metadata, task 3. Kyo itself needed nothing. The MCP server
   stays JVM (MIP §4).
2. **`:jvm` base:** `eclipse-temurin:25-jre-alpine` (71 MB, 2026-08-21; `25-jre` is 111 MB —
   both checked on Docker Hub 2026-09-05). No `jlink` for v1: the 40 MB it might save is not
   worth a second build path. Builder: `sbtscala/scala-sbt:eclipse-temurin-25.0.4_7_1.13.0_3.8.4`
   (466 MB, 2026-09-05). Native builder `ghcr.io/graalvm/native-image-community:25`, runtime
   `gcr.io/distroless/base-debian12:nonroot` (both manifests answered 200 on 2026-09-05).
3. **Smoke test cadence:** daily at 09:30 UTC (06:30 in Brazil, before the morning swim) plus
   on demand. Never per PR (MIP §8: ~5 min of runner per run).
4. **Where the smoke result lives:** the orphan `site-data` branch, copied into `site/dist/smoke/`
   by `site.yml`; the smoke workflow never deploys Pages itself (MIP §5.5).
5. **Tier 2 adapter:** not in v1. `marola-local` is the Tier 1 Modelfile model on `llama3.2`
   (`finetune/README.md` says so already); an adapter shipped as a release asset is a later task,
   once something has trained it.
6. **The panel is on the public map**, in the footer, labelled as a live run of the model with the
   reviewer's verdict next to it; a `reject` verdict hides the sentence and keeps the numbers.
   A separate `/status.html` is not worth a second page for one panel.
7. **Platforms:** `:jvm` and `:dev` for `linux/amd64` and `linux/arm64` (the jar is built once, on
   the build platform, and copied into each); `:native` and `:local` for `linux/amd64` only
   (native-image does not cross-compile; the Ollama model store is platform-independent but the
   base image build is done once).
8. **Ollama in compose** is the official `ollama/ollama:latest` (3.5 GB, 2026-09-03), pulled once
   into a named volume; CI uses the ~100 MB binary as `marola-e2e.yml` does.
9. **Benchmark gate metric:** `rag-general` coverage (all) from the summary table, compared with
   the newest file in `docs/benchmarks/` — a drop of more than 0.05, or falling below `baseline`,
   fails the job. One number, the one `docs/benchmarks/2026-09-05.md` calls "the result that
   matters".
