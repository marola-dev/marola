## Decisions

Decisions 1–4 were accepted by the maintainer on 2026-10-02 and are written into the MIP's §5.7
and §7.

1. **Landings come before the pair.** Task 18's landing rule refuses any repo with both
   `README.md` and `docs/index.md`, and all seven have both today. So the landings of devkit,
   site, corpus, ml and oods (tasks 9, 12–15) land first; each is safe on today's aggregator,
   which already copies a README when `docs/index.md` is absent.
2. **`docs-lint` (c) exempts the umbrella's own `docs/1-Using-marola` and `docs/2-Building-marola`**,
   which §7's `agents_repos_check.sh` itself requires `AGENTS.md` to name (task 1's
   `umbrella_owns_its_numbered_dirs_ok`). Rule (d) fails in every repo until its landing, so each
   repo gates on `docs-lint` in its last content row (9, 15, 22, 24, 25, 31, 32).
3. **The pair is tasks 17 and 18, merged back to back, and it moves URLs only.** Task 18's CI
   builds against task 17's head (PR builds read the gitlinks), then task 17 merges, task 18
   re-pins to its squash commit and merges. Between the two merges `docs.yml` is red and the site
   stays on its last good deploy. The umbrella receives RUN-LOCALLY, TELEGRAM-SETUP and
   ARCHITECTURE with links fixed only; every Appendix B URL is served from task 18 on, so the
   org pages and rewrites (23, 27–30) change content, never URLs. The pair is reviewed on
   prepare-docs and the config files; moves and deletions are excluded, as in MIP-0070's
   Decision 5.
4. **marola-ml adopts the `api-docs` workflow before the pair** (task 11). Otherwise its pdoc
   vanishes from the site after task 18, and the app's `4-reference_api` link to it fails
   Appendix A's broken-link rule.
5. **Umbrella content ships one PR per section** (maintainer, 2026-10-02: bigger reviews
   accepted): 1 Using (23), 2 Building (27), 3 Ways of working (28), 4 Research (29), the landing
   and root pages (30). The build tasks (3–8, 16, 18, 19) stay small and separate.
6. **Content flows one way, and each file is rewritten once.** App material that task 18
   receives in the umbrella's copies (ARCH §3, §5, §7, §8–9's internals; RUN-LOCALLY §7, §9–11) is
   written into app pages first (20, 21, 24), and only then removed from the umbrella page with a
   stub (23, 27, 29). ARCHITECTURE is touched by 18 (received), 23 (§8–9 stubbed) and 27 (the
   rest, keeping 23's stubs); DEV-FLOW §1 by 23 (RUN-LOCALLY §8 merged in) and 28 (the rest,
   keeping §1's merged text). The app's heuristics page (24) links LIMITATIONS, so section 1 (23)
   precedes it and section 2 (27) follows it.
7. **Anchors fixed in advance.** Task 26 cites `#local-first-integration-pattern`, the heading
   task 27 must keep, so the devkit's `v0.3.1` does not wait on the umbrella's rewrite.
8. **Each repo's README grows with its pages.** The landing rows link only pages that exist; each
   later page row adds its own line, so no row rewrites a README another row just wrote.
9. **Cross-repo rows stack per repo.** `stack start` bases a branch on that repo's previous
   MIP-0074 branch; the `depends on` column is the real graph across repos, and a row whose
   dependency is in another repo starts once that PR has merged.
10. **Human-only steps**: creating `marola-dev/.github` (33), and the after-deploy checks (18, 37),
    which need the live site. Each is named in its row, so the issue isn't `agent-ready` until the
    person doing it is assigned.
